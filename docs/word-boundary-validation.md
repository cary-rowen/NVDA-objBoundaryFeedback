## 自动化覆盖的具体行为

- UIA 与 Legacy Word：上下键、Ctrl+上下，空文档、单行、多行末端，方向正确且只提示一次。
- Legacy 段落导航实际执行官方 COM 脚本；不发出额外按键，不引入等待或文本范围试探。
- 正常移动，包括刚到达边界；取消选区；焦点/内容变化；等待被后续脚本或焦点打断。
- Legacy 原生按键绑定、用户手势映射、非键盘重绑定及 say-all 元数据。
- 浏览模式 Home/End 的行范围查询抛出异常时，保留原有提示；正常虚拟光标移动不误报。
- 单行/多行分段辅助函数、各场景可用提示模式的消息/当前项目/声音及原函数返回值。
- 插件卸载恢复方法及已存在、新创建的 Legacy Word 对象手势表。
- 其他导航键、非 Word 控件、未识别手势保持原有检测逻辑。

官方调用路径测试使用真实 NVDA 类和实现，应用数据由可控 provider 提供。
这些结果不等于真实 Word 两种后端的桌面端到端测试已经完成。Robot Framework 已安装，
但没有启动会替换当前 NVDA 进程的官方桌面系统测试；本次作者要求的回归由上述自动化测试覆盖。

## 人工验收清单

安装第二版测试包并重启 NVDA。将“可编辑文本光标边界”设为“NVDA 默认和提示音”。
先在现有环境测试，再分别明确切换 Word UIA 为启用和禁用；重新打开文档后核对 NVDA 实际对象后端。
“UIA 默认”只记录设置值，不能据此宣称两个后端均已实测。

| 场景 | 预期 |
| --- | --- |
| 空文档、单行文本 | 上/Ctrl+上越界播放上边缘音，下/Ctrl+下越界播放下边缘音 |
| 多段落、自动换行的长段落 | 正常移动无提示；真正越界时方向正确 |
| 末尾空段、多空段、Shift+Enter | 根据实际移动结果提示，不把可继续移动的位置当成边界 |
| 首/末行的不同列位置 | 位置发生变化时无音；后续无法继续移动时提示 |
| 选中部分文字或全文 | 取消选区时不误报 |
| 连续按键、长按、切换焦点 | 不因等待中断或焦点转移补播错误提示 |
| 表格、文末表格、页眉页脚 | 原生移动及朗读保持正常；无法继续时按方向提示 |
| 单行/多行分段导航设置 | 保留该模式自身的边界反馈及回退行为 |
| 浏览模式、对象导航、浏览光标、快速导航 | 原有提示及配置行为保持一致 |
| 左右、Ctrl+左右、Home/End、Page Up/Down、Ctrl+Home/End、其他编辑器 | 与作者原版一致；本版未重定义这些按键的边界规则 |
| “NVDA 默认” | 不增加插件提示音，原生导航及朗读保留 |
| 重载插件或重启 NVDA | 不出现重复提示、残留钩子或日志异常 |
